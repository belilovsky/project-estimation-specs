# Как предложить исправление

Обсуждение состава и более простые способы получить тот же результат приветствуются. Владелец репозитория — belilovsky; предложение можно оставить в GitHub Issue или Pull Request этого репозитория.

Укажите проект, версию, W-ID / R-ID / C-ID / OP-ID, спорную формулировку, причину и предлагаемую замену. Если готовый компонент сокращает работу, назовите версию, лицензию, покрытие требований, остающиеся доработки и расходы. Количество звёзд и рекламное обещание не заменяют проверку.

Для ошибочного объёма покажите единицу, правила подсчёта, дубли и разрешённый воспроизводимый пример. Не прикладывайте закрытый корпус, внутреннюю калькуляцию, персональные данные, токены и предложения третьих лиц без разрешения.

Изменения общего шаблона должны помогать другим продуктам. Специфические требования остаются в папке проекта. При исправлении внешнего комплекта сначала меняют его собственный репозиторий, затем обновляют закреплённый указатель здесь.

Перед предложением изменений выполните команды из [README](README.md). Прохождение проверки не означает юридической, редакционной или рыночной приёмки. Не помечайте независимой рецензией самопроверку автора.

Если замечание содержит секрет или уязвимость действующего продукта, не открывайте его публично. Используйте непубличный канал владельца продукта; этот каталог не принимает доступы и производственные журналы.
